# ポポさんぽ 構成案

「ポポさんぽ」をこれからどう組み立てて、どう育てていくかの案です。
いまの構成（できていること）と、次に作るものの順番、Google Health 連動の道すじをまとめました。

- 版：v0.1（2026-09-08）
- 関連：`docs/spec.md`（いまの機能の説明書）

---

## 1. いまのファイル構成

```
popo-sanpo/
├── index.html        画面・動き・保存が1ファイル
├── manifest.json     ホーム画面に追加するための設定（名前・アイコン）
├── sw.js             オフライン用（ファイルを覚えておく）
├── img/
│   ├── popo_idle.png     ふつう
│   ├── popo_walk.png     さんぽ中
│   ├── popo_good.png     グッド
│   ├── popo_yay.png      やったー
│   ├── popo_sparkle.png  きらきら
│   ├── icon-192.png      ホーム画面アイコン
│   └── icon-512.png
├── docs/
│   ├── spec.md       仕様書
│   └── plan.md       構成案（この文書）
└── README.md
```

ポイント
- サーバーなし。全部「静的ファイル」なので GitHub Pages にそのまま置ける。
- 画面は `index.html` の1ファイル完結。初心者でも「この1枚を直せばいい」状態にしてある。
- ファイル名は英語。将来のアプリ化や URL の短さのため。

## 2. 画面の流れ

画面は1つ。ポポの状態が切り替わる。

```
ふつう ──スタート──▶ さんぽ中 ──ストップ──▶ えらい
   │                    │
   └──── 目標達成 ──────┘──▶ やった（3.5秒）──▶ きらきら
```

## 3. 技術の構成（いま）

| 層 | 使っているもの | 理由 |
|---|---|---|
| 画面 | HTML / CSS（1ファイル） | ビルド不要。GitHub 上で編集して即反映 |
| 動き | 素の JavaScript | ライブラリ不要で軽い |
| 歩数 | DeviceMotion（加速度センサー） | Webで使える唯一の歩数手段 |
| 保存 | localStorage | 登録不要・オフラインOK |
| 配信 | GitHub Pages（https） | 無料。センサーに必要な https を満たす |
| オフライン | Service Worker | 電波がなくても開ける |

## 4. データの構成

いまは端末の中だけ（`popo_sanpo_v1`）。

```
days  : 日付 → 歩数
bonus : 日付 → ボーナス済み
goal  : 目標歩数
```

将来サーバーを持つときも、この形をそのまま送れるようにしておく（日付ごとの歩数が基本単位）。

## 5. 育てる順番（ロードマップ案）

### 段階1：いま（v0.1）— 動くPWA
- センサー歩数・ポイント・目標・ボーナス・週グラフ・同期入力。
- **やること**：main にマージして GitHub Pages で公開し、実際に歩いて精度を見る。

### 段階2：ポイントの使い道とごほうび（v0.2）
ポイントが「貯まるだけ」だと飽きるので、使い道をつくる。
- ポポの表情コレクション：ポイントで新しい表情を解放（設定書の「泣く」「はてな」「ハート目」などを使う）。
- 連続達成バッジ：3日・7日・30日連続で目標達成。
- 五円玉モチーフ：ポイントを「ご縁」として見せる演出。500pt = 五円玉1枚、など。
- 通知：夕方に「きょうはあと ◯ 歩だね！」（PWA通知は Android のみ確実）。

### 段階3：Google Health（ヘルスコネクト）との自動連動（v0.3）
くわしくは次の章。ここで「Webのまま」か「アプリ化」かを決める。

### 段階4：アカウントと pointpay 連携（v1.0）
- ログインして複数端末でポイントを共有。
- ポイントをお店で使う／お店を応援する仕組み（ポポの「招きネコ活動」）。
- ここで初めてサーバーとデータベースが必要になる。

## 6. Google Health 連動の道すじ

### 前提（大事）
- **ヘルスコネクト（Android）も ヘルスケア（iPhone）も、Webページからは読めない。** 読めるのはインストール型のアプリだけ。
- Google Fit の Web 向け API は廃止済み。新しく作るなら選べない。

### 選択肢

| 案 | 内容 | 良い点 | 大変な点 |
|---|---|---|---|
| A. いまのまま（手入力同期） | 歩数アプリの数字を入力 | すぐ使える。無料。いま実装済み | 毎日手で入れる |
| B. Android アプリ化（おすすめ） | いまの画面を Capacitor で包み、ヘルスコネクトのプラグインで歩数を読む | 画面はそのまま使い回せる。自動で正確な歩数が入る | Google Play 登録（開発者登録 $25）。ヘルスコネクトの審査あり |
| C. iPhone も対応 | 同じ包みで HealthKit を読む | iPhone でも自動 | Apple 開発者登録（年 $99）。Mac が必要 |

### おすすめの進め方
1. 段階1・2 を Web のまま進めて、遊びとして面白いかを先に確かめる。
2. 面白さが確認できたら **B（Android アプリ化）** に進む。画面は `index.html` を流用する。
3. ヘルスコネクトから読むのは「今日の歩数の合計」だけにして、権限を最小にする（審査が通りやすい）。
4. 読んだ歩数は、いまの「同期する」と同じ処理（多いほうに合わせる）に流し込む。

### アプリ化したときの構成イメージ

```
[ポポさんぽ 画面（index.html）]
          │  JavaScript から呼ぶ
[Capacitor（Web を包む箱）]
          │  プラグイン
[ヘルスコネクト（Android）] ─ 歩数を読む
```

## 7. 公開と運用の流れ

1. 小さな直しは `main` に直接入れる。大きな変更はブランチを作ってプルリクエストで入れる。
2. GitHub Pages（Settings → Pages → Branch: main）で公開。数分で反映。
3. スマホで `https://193murano-cmyk.github.io/popo-sanpo/` を開き、ホーム画面に追加。
4. 直したいことはチャットに書けば、同じ流れで反映できる。
