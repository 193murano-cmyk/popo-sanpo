# ポポさんぽ 仕様書

歩くとポイントが貯まるアプリ「ポポさんぽ」の、いまの姿をまとめた説明書です。
「何ができるか」「どういうルールか」「どこに限界があるか」を、この1枚で分かるようにしています。

- 版：v0.1（2026-09-08）
- 対象ファイル：`index.html`
- 関連：`docs/plan.md`（これからどう育てるかの案）

---

## 1. アプリの目的

- 毎日のおさんぽを「ポポと一緒に歩く」楽しい体験にして、続けやすくする。
- 歩いた分だけポイントが貯まり、目標を達成するとポポが喜ぶ。
- 将来的には、貯まったポイントをお店や pointpay の世界とつなげる土台にする。

## 2. 使う人と場面

| 誰が | いつ | どうやって |
|---|---|---|
| スマホを持って歩く人 | 通勤・散歩・買い物のとき | スマホのブラウザで開き、ホーム画面に追加して使う |

- 会員登録やログインは不要。
- データはそのスマホの中だけに保存される（サーバーには送らない）。

## 3. キャラクター「ポポ」

設定書（`ポポ.md` / `pointpay_chara_story.pdf`）にもとづく。

- ふわふわの綿毛をもつ、ネコのようなふしぎな生き物。赤いからだ、白い綿毛の雲、首もとの五円玉。
- 一人称は「ぼく」。語尾は「〜だね！」。口癖は「風がとおるよ」。
- 夢は日本一の「ニャンフルエンサー」。

アプリでの表情（画像ファイル）

| 状態 | 画像 | いつ出るか |
|---|---|---|
| ふつう | `img/popo_idle.png` | 何もしていないとき |
| さんぽ | `img/popo_walk.png` | 「さんぽスタート」中。ゆらゆら動く |
| えらい | `img/popo_good.png` | 「ストップ」を押したあと |
| やった | `img/popo_yay.png` | 目標を達成した瞬間（約3.5秒） |
| きらきら | `img/popo_sparkle.png` | 目標達成済みのあいだ。まわりが金色に光る |

## 4. 機能一覧

| # | 機能 | 説明 |
|---|---|---|
| 1 | 歩数カウント | スマホの加速度センサーで揺れを読み、歩数を数える |
| 2 | ポイント | 1歩 = 1ポイント。「きょう」と「ぜんぶ」を表示 |
| 3 | 1日の目標 | 1,000 / 3,000 / 5,000 / 8,000 / 10,000歩から選ぶ（初期値 3,000） |
| 4 | 目標ボーナス | その日はじめて目標に届いたとき +500ポイント。1日1回だけ |
| 5 | 進み具合バー | 目標に対する今日の歩数を帯で表示。残り歩数も表示 |
| 6 | 1週間グラフ | 今日を含む直近7日の歩数を棒グラフで表示。達成日は金色 |
| 7 | 歩数アプリと同期 | Google Fit・ヘルスコネクト等に出ている「今日の歩数」を入力すると、その数に合わせる |
| 8 | 手動で足す | センサーが使えない端末向け。+10歩 / +100歩ボタン（ポポを長押しで表示） |
| 9 | 画面を消さない | さんぽ中は画面が自動で暗くならないようにする（対応端末のみ） |
| 10 | オフライン対応 | 一度開けば、電波がなくても開ける（Service Worker） |

## 5. 画面の構成（上から順に）

1. ヘッダー：タイトル「ポポさんぽ」
2. ポポの絵（状態で切り替わる）
3. きょうの歩数（大きな数字）
4. 進み具合バー＋「目標まであと ◯ 歩」
5. ポイントカード：「きょう」「ぜんぶ」
6. 「さんぽスタート」ボタン（さんぽ中は青い「ストップ」になる）＋ポポのひとこと
7. 手動ボタン（ふだんは隠れている）
8. 歩数アプリと同期する欄
9. 1日の目標を選ぶ
10. この1週間のグラフ
11. 注意書き

## 6. ポイントのルール

- 1歩 = 1ポイント。
- 目標達成ボーナス = 500ポイント。その日に初めて目標に届いたときだけ。
- 「きょう」= 今日の歩数 ＋（今日ボーナスがあれば 500）。
- 「ぜんぶ」= 記録のあるすべての日の「きょう」の合計。
- ポイントは減らない。歩数を同期で低い数に合わせようとしても減らさない。
- 日付は端末の時計で判定し、深夜0時で日が変わる。

## 7. 歩数を数えるしくみ

1. 加速度センサーの値（重力込み）の大きさを取る。
2. ゆっくり変わる成分（重力）を追いかけて引き算し、「動き」だけを取り出す。
3. 動きがしきい値（1.1 m/s²）を超えた瞬間を1歩と数える。
4. 前の歩から 280ms 以内は数えない（ぶれ防止）。

iPhone は「さんぽスタート」を押したときにセンサー利用の許可画面が出る。Android は許可なしで動くことが多い。

## 8. 保存されるデータ

ブラウザの localStorage にキー `popo_sanpo_v1` で保存。

```json
{
  "days":  { "2026-09-08": 3120, "2026-09-07": 2400 },
  "bonus": { "2026-09-08": true },
  "goal":  3000
}
```

- `days`：日付ごとの歩数
- `bonus`：その日にボーナスをもらったか
- `goal`：1日の目標歩数

ブラウザのデータを消すと記録も消える。別の端末には引き継がれない。

## 9. 動作環境と制限

| 項目 | 内容 |
|---|---|
| 必須 | https で開くこと（GitHub Pages は https） |
| 対応 | iPhone Safari / Android Chrome。ホーム画面に追加するとアプリのように使える |
| 制限 | 画面を消灯するとカウントが止まる（ブラウザの制限）。バックグラウンドでも止まる |
| 精度 | 専用の万歩計アプリより粗い。ポケットに入れて歩くと多めに数えることがある |
| 対策 | 歩数アプリの数字を「同期する」欄で入れれば、正確な数に合わせられる |

## 10. Google Health（ヘルスコネクト / Google Fit）との連動について

現状の結論：**Webページからは直接読めない。**

- Android の「ヘルスコネクト」は、スマホにインストールする本物のアプリ（ネイティブアプリ）だけが読める仕組み。Webページ用の窓口がない。
- iPhone の「ヘルスケア」も同じで、ネイティブアプリだけが読める。
- 以前あった Google Fit の Web 向け API は廃止済みで、新しく使うことはできない。

なので v0.1 では「歩数アプリの数字を入力して合わせる」形にしている。
本当に自動で連動するには、アプリをネイティブ化する必要がある。その道すじは `docs/plan.md` に書いた。

## 11. 用語

- PWA：ホーム画面に追加できて、オフラインでも動くWebページ。
- Service Worker：オフラインで動かすためにファイルを覚えておく仕組み。
- localStorage：ブラウザの中の小さな保存場所。
- ヘルスコネクト：Android で歩数などの健康データをアプリ同士で共有する仕組み。Google Fit の後継。
